Ironworks — Set Logging & Lift History

concept · extends ironworks-pplppl7 · 2026-07-25

PPLPPL 7 flows Production app
  • Three ideas, one decision. Frame 1 (inline sets) and frame 2 (logger sheet) are two alternative input models — pick one. Frame 3 (exercise history) and frame 4 (day sheet) are read views that work with either.
  • Ghost prefill is the core trick. Pending sets show last session's weight/reps in faint. Repeat a set exactly = one tap on ✓. Change it = steppers first (±2.5 kg, ±1 rep), then ✓. "What did I do last time" is answered without opening anything.
  • Completion derives from logging. When all prescribed sets are confirmed the entry checks itself; the meta line shows progress (2/3 @ 60) meanwhile. Manual check stays for untracked optional work. Logged rows replace the prescription with actuals; upcoming rows show last … instead.
  • Trade-off to decide: row tap currently opens the reference. With logging, row tap should open logging (the between-sets task); reference moves to a link inside the expanded area / sheet. The video button is untouched.
  • Data model. sessions[date].logs[entryId] = { exerciseId, sets: [{kg, reps}] } — keyed to the master exercise actually used, so multi-choice slots log per choice. Timed prescriptions log seconds (45s); bodyweight logs reps only. History (frame 3) is derived from these logs — no separate PR table.
  • Deliberately excluded: charts, trends, 1RM estimates, plate math, streaks, volume dashboards. The rest chip appears only after a confirmed set and dismisses itself; it is a convenience, not a feature area.
